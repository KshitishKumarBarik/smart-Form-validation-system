Understanding Variables & Scope

Learn the difference between global, function, and block scope, and why variable leakage is a critical bug in production environments.

Q: What is the difference between global, local, and block scope in JavaScript?
High-Scoring Answer:
- Global Scope: Variables declared outside of any function/block. Accessible anywhere. If defined with var, they attach to window (in browsers).
- Local/Function Scope: Variables declared inside a function are isolated inside that function. Introduced by var, let, and const.
- Block Scope: Introduced in ES6. Variables declared with let or const inside curly braces {} (like if, for) are block-scoped and cannot be accessed outside. var ignores block scope.
Q: What is "variable leakage" and why is it dangerous?
High-Scoring Answer: Variable leakage happens when you assign a value to an undeclared variable (forgetting const, let, or var). JavaScript implicitly creates it in the global scope. This causes conflicts (pollutes the global namespace), memory leaks, and hard-to-track bugs. Enable "use strict"; at the top of your scripts to throw a ReferenceError when this happens.

DOM Manipulation & Event Listeners

How the browser triggers event callbacks, and how we dynamically update UI nodes to provide feedback to users without page reloads.

Q: Explain a real-world scenario where you would use DOM manipulation.
High-Scoring Answer: "In a smart form system. I attach input event listeners to inputs to perform live validation. Using DOM APIs like querySelector, I look up helper elements, then toggle visibility and append classes like .is-invalid. I also change element properties, like toggling an input's type from password to text when the user clicks a show/hide button. This increases accessibility and usability."
Q: Which input event listener should you use for forms? (change vs input)
High-Scoring Answer: Use the input event for real-time validation. It fires instantly every time the value of an <input>, <select>, or <textarea> changes. The change event only fires when the element loses focus (blurs) after a modification, which feels less responsive for live strength meters or checks.
Code Example: DOM Querying & Toggles 
// Querying the DOM nodes
const emailInput = document.querySelector("#email");
const errorSpan = document.querySelector("#email-error");

// Attaching dynamic input listener
emailInput.addEventListener("input", function(e) {
  const value = e.target.value;
  
  if (validateEmail(value)) {
    // DOM style/class manipulation
    emailInput.classList.add("valid");
    emailInput.classList.remove("invalid");
    errorSpan.innerText = ""; // Clear text
    errorSpan.style.display = "none";
  } else {
    emailInput.classList.add("invalid");
    emailInput.classList.remove("valid");
    errorSpan.innerText = "Please enter a valid email format";
    errorSpan.style.display = "block";
  }
});

Regex, DNS Validation & Async Fetch

Validating textual input structures mathematically and performing real-time domain checking using DNS-over-HTTPS API lookups.

Q: How do you write a regular expression to validate emails in JavaScript?
High-Scoring Answer: "While a perfectly RFC 5322-compliant email regex is extremely complex, for standard client-side forms we use a pattern like: /^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$/.
- ^ and $ assert start and end of string.
- [\w-\.]+ matches letters, numbers, hyphens, and dots before the @.
- @ matches literal '@' symbol.
- ([\w-]+\.)+ matches the domain name and dot.
- [\w-]{2,4} matches top-level domain extensions of length 2 to 4."
Q: How do you check if an email's domain actually exists and can receive mail? (MX Record check)
High-Scoring Answer: "While a regex validates the *syntax* of an email, it cannot check if the domain is real or active. To verify if a domain can receive mail, we look up its **MX (Mail Exchanger) DNS records**. Since browsers cannot run raw DNS queries due to security and sandbox restrictions, we query a public **DNS-over-HTTPS (DoH)** API (like Cloudflare's) using fetch with the application/dns-json header. This is done asynchronously (e.g. on input blur), showing a loading state so it doesn't block the UI thread."
Q: Why is client-side validation important if server-side validation is mandatory?
High-Scoring Answer: Client-side validation is for User Experience (UX). It provides instant, satisfying feedback without round-trip network delays, saving server bandwidth. Server-side validation is for Security, because client-side code can be bypassed easily by disabling JS, tampering with requests, or using APIs directly.
Code Example: Regex & DNS lookup 
// Reusable validation function using Regex
function validateEmail(email) {
  const emailRegex = /^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$/;
  return emailRegex.test(email);
}

// Asynchronous MX Record validation using DNS-over-HTTPS
async function checkMXRecord(email) {
  const domain = email.split("@")[1];
  if (!domain) return false;
  
  try {
    const url = `https://cloudflare-dns.com/dns-query?name=${domain}&type=MX`;
    const response = await fetch(url, {
      headers: { "accept": "application/dns-json" }
    });
    const dnsData = await response.json();
    
    // DNS Status 0 = NOERROR. Check if Answers exist with MX type (15)
    return dnsData.Status === 0 && dnsData.Answer && dnsData.Answer.length > 0;
  } catch (err) {
    console.error("DNS Lookup failed:", err);
    return false; // Fallback or fail-safe
  }
}

function checkPasswordStrength(password) {
  const hasNumber = /[0-9]/.test(password);
  const hasCapital = /[A-Z]/.test(password);
  const hasSpecial = /[!@#$%^&*]/.test(password);
  
  return { hasNumber, hasCapital, hasSpecial };
}

Objects & ES6 Destructuring

Collecting local variables into organized state objects, and cleanly breaking them apart using modern syntax instead of dot notation.

Q: Why should we store form data in an object rather than separate variables?
High-Scoring Answer: Storing data in a single object like const formData = { email: '', password: '' } gives us a "single source of truth". It makes it clean to pass the data to API callers, serialize it to JSON, reset states, and perform batch operations. It aligns with modern state-management patterns in frameworks like React.
Q: Explain object destructuring and its benefits.
High-Scoring Answer: Destructuring is an ES6 feature allowing us to unpack values from arrays or properties from objects into distinct variables. It reduces boilerplate code. Instead of writing:
const email = formData.email;
We write:
const { email, password } = formData;
It is highly readable, permits setting default values, and allows renaming variables inline (e.g. const { email: userEmail } = formData;).
Code Example: Object Handling & Destructuring 
// State object representing form values
const formData = {
  username: "",
  email: "",
  password: ""
};

// Submitting the data
